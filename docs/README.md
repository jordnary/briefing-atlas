## 本地文档

计划、任务规则、内部运行约定、实施和验证记录统一放在 `docs/local/`。该目录整体被 `.gitignore` 忽略，不进入云端仓库；首次克隆后按需创建。当前本地材料按以下三个文件归纳：

| 相对路径                   | 用途                                       |
| -------------------------- | ------------------------------------------ |
| `docs/local/PLAN.md`       | 当前决策、剩余工作与完成条件               |
| `docs/local/OPERATIONS.md` | 原任务规则、定时探针与日常操作             |
| `docs/local/VALIDATION.md` | 合并后的实施证据、历史验证范围与未验证事项 |

公开文档只链接仓库内可用的指南，不依赖本地文件才能理解或执行。`.gitignore` 另拦截旧 `doc/`、`*.local.md`、`*_PLAN.md`、`*_IMPLEMENTATION.md`、`*_READINESS.md` 和 `VALIDATION.md`，减少内部文档在旧位置重新加入版本控制的机会。其他内部材料仍须放入 `docs/local/`，不能只依赖文件名规则。

## 维护约定

- 长期有效的使用方法和接口约定放入对应指南；相同主题更新原文，避免另建一份近似说明。
- 计划完成后保留仍有效的决策和待办，清除过期执行清单；测试次数、截图、运行回执和个别环境结果只记在本地。
- 原始输入留在 `incoming/`，同步状态和检查点留在 `work/`，截图和测试产物留在 `test-output/`。这些是已忽略的工作数据，不作为文档搬迁或提交。
- 示例使用相对路径和通用标识，不写入用户名、设备名、虚拟环境名、绝对路径、私人对话标识或凭据；本地文档同样遵守。
- `.gitignore` 只阻止未跟踪文件被正常加入。已跟踪的私有文件迁入本地目录后，需提交原路径的删除；旧提交中的内容不会因此消失。不要对本地资料使用 `git add -f`，也不要把它们加入分发压缩包或构建产物。
