OpenAI 正在开发 Codex 的 **Persistent Mode**。据 WIRED 8 月 27 日报道，这种模式不再要求 Agent 完成一次任务后停止，而是可以持续运行，主动生成后续任务，并在必要时向用户发送通知；目前仍处于测试阶段，尚未正式发布。[WIRED](https://www.wired.com/story/openai-is-developing-a-persistent-ai-agent?utm_source=chatgpt.com)

**为什么重要：** 这代表 Coding Agent 的竞争目标正在发生根本变化：从 `Prompt → 写代码 → 结束`，转向 `目标 → 执行 → 检查 → 发现新任务 → 继续执行`。真正的竞争指标将逐渐变成 Agent 能否可靠工作数小时、数天甚至更久，而不是单次 benchmark 得分。

**实践 / 研究启示：** 对 Agent 开发而言，接下来尤其值得学习 **Harness Engineering、任务队列、状态持久化、权限控制、自动验证、checkpoint 和长期上下文管理**。这些工程能力很可能比单纯 Prompt Engineering 更重要。

Anthropic 8 月 27 日开放了 **Model Hardware Standard（MHS）**研究预览，这是一个让 AI Agent 安全操作现实物理设备的共享规范，首批应用重点放在科研实验室。[Anthropic](https://www.anthropic.com/news/model-hardware-standard-research-preview?utm_source=chatgpt.com) · [Open Model Hardware Standard](https://github.com/SCUT-ESA/open-mhs)

**MCP：Agent ↔ 软件 / 数据 / API**

**MHS：Agent ↔ 仪器 / 实验设备 / 现实世界**

Anthropic 同期也在扩大 Claude 面向科学家的能力和项目支持，因此这并不像一个孤立协议，而更像是其 **AI for Science + Physical Agent** 战略的一部分。[Anthropic](https://www.anthropic.com/news/expanding-support-for-scientists?utm_source=chatgpt.com)

**为什么重要：** 一旦模型能够通过标准化接口可靠控制实验仪器，Agent 就可能完成 `读论文 → 提出假设 → 设计实验 → 操作设备 → 分析结果 → 修改实验` 的闭环。AI 的作用由“辅助研究人员”向“参与实验过程”推进。

**实践 / 研究启示：** MCP、Computer Use 和 MHS 可以看成同一条技术路线：**让 LLM 从语言模型变成环境中的执行主体。** 游戏引擎其实也是极好的 Agent 环境——Agent 操作 Unreal、Unity 或 Godot，与科研 Agent 操作实验仪器在架构上存在很强的共通性。
