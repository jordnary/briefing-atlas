OpenAI 于 11 月 4 日宣布将收购 Pierre Computer Company。Pierre 的 Trees 文件树和 Diffs 差异渲染库已经用于 Codex，收购计划还涉及 Git 存储服务 Code Storage。公告明确区分了现状与后续整合：开源项目将保持开源，客户在交割后仍可使用 Code Storage；交易须满足监管批准等惯常交割条件，在此之前双方继续独立运营。公告没有披露成交金额，也没有宣布一个已经上线的新代码托管平台。[来源：OpenAI，OpenAI to acquire Pierre Computer Company, Inc.；发布及收购计划公告：2026-11-04](https://openai.com/index/openai-to-acquire-pierre/)。

同日，Conductor 宣布加入 Meta，并给出现有用户更直接的迁移时间表：11 月 4 日停止新用户注册及应用下载；Conductor Cloud 将于 11 月 13 日转为只读，11 月 20 日关停并开始删除云端用户数据。现有用户需在该日期前完成导出；本地版继续获得新模型和关键修复至 2027 年初，再逐步收尾。团队预计明年初提供新产品，但尚未公开具体功能。这里新增的是并购后的服务安排，不能把未来产品当作已有替代方案。[来源：Conductor，Conductor is joining Meta；公告及 0.93.0 更新发布：2026-11-04；未来日期均为公司给出的日历日期，未披露具体时区及切换时刻](https://www.conductor.build/announcement)；[0.93.0 更新说明](https://www.conductor.build/changelog/0.93.0-conductor-is-joining-meta)。

两则消息共同显示，竞争范围已从生成代码扩展到存储、审查和代理协作；但对使用者而言，继续服务的承诺和明确的退出期限需要分别处理。Pierre 的工具已经嵌入现有工作流，后续应观察 API 兼容性、开源维护和实际整合节奏。Conductor Cloud 用户则应优先清点未合并分支、未提交修改及聊天中的决策依据；官方提供右键工作区选择 Transfer to local，以及 Settings → Account → Export data 的迁移和导出入口。导出后应抽查代码、分支和对话是否完整，并验证本地构建所需依赖；迁移完成不能仅以下载了压缩包为准。[来源：Conductor 公告的 Timeline、FAQ 及官方更新中的导出说明](https://www.conductor.build/announcement)。

时间范围说明：两家公司的一手公告均标注 11 月 4 日，未取得可确认的精确发布时间。本条按 72 小时上下文窗口纳入，保留代码基础设施整合与即将到来的迁移期限，不推测交易交割日或服务切换时刻。

Cloudflare 在 11 月 4 日发布个人代理流量分析与细粒度访问控制。Security Analytics 的 Bot analysis 新增 Personal Assistants 类别，Top statistics 列出已识别代理的请求数，并可联动查看请求路径、状态码与来源网络。对于处于 early access 的 Account Abuse Protection，登录及注册事件还可以关联代理和账户，帮助调查某个账户是否突然出现新的代理访问。[来源：Cloudflare，See the agents, set the terms: new visibility and control for personal agents；发布及功能公告：2026-11-04，页面元数据为 14:00 UTC，即北京时间 22:00](https://blog.cloudflare.com/personal-agents-visibility-control/)。

网站可以设置整体 Agents 策略，再为受支持的个人代理选择 Allow (do not block)、Block on pages with ads 或 Block。原先的 Search、Training 策略继续分别保留，设置入口更名为 AI Crawler and Agent access policies。这使站点能在观察流量后区分对待不同代理，而不必把所有自动访问作为同一类别处理；公告没有承诺识别所有代理，也没有说识别到品牌就能证明请求已获用户授权。[来源：同一公告的 See how agents access your site 与 Set access policies 章节](https://blog.cloudflare.com/personal-agents-visibility-control/)。

实际边界在于用户上下文。Cloudflare 将会员资格、用户究竟授权了什么、订阅状态和责任机制列为下一阶段工作，不能把这些未来目标写成现成能力。网站团队可以先按代理检查读取、登录和结账路径的状态码及错误率，再在测试流量中验证策略是否误伤正常访问；对敏感操作继续使用独立的身份校验和业务授权。代理开发者则应记录站点返回的明确拒绝与失败环节，尊重站点政策，避免把“能发出请求”当作完成用户任务的依据。[来源：官方公告的 Agent identity is only part of the story 章节；以上验证步骤为基于该边界的实践建议](https://blog.cloudflare.com/personal-agents-visibility-control/)。

NVIDIA 于 11 月 4 日发布 CUDA 13.5 技术公告：Vera Rubin GPU 架构支持从早期开发者访问推进至 general availability；Windows on Arm 已在 13.4 达到 GA，本次进一步扩展至 DGX Station for Windows。公告元数据时间为 18:46 UTC，对应北京时间 11 月 5 日 02:46。对部署团队，新增支持范围比笼统的“CUDA 又提速”更关键：从 Rubin 起，Windows 使用 WDDM 或面向计算的 MCDM，TCC 不再受支持，依赖旧驱动模式的部署脚本需要检查。[来源：NVIDIA，NVIDIA CUDA 13.5 Brings NVIDIA Vera Rubin GA Support；发布及更新公告：2026-11-04](https://developer.nvidia.com/blog/nvidia-cuda-13-5-brings-nvidia-vera-rubin-ga-support/)。

本次 CUDA Tile 更新允许在内核内进行多 GPU 通信：unicast 指针用于访问 NVLink 连接的其他 GPU，multicast 与 multimem 操作面向具备相应 NVLink SHARP 支持的 NVSwitch 网络。Tile 调用 SIMT 库设备函数仍是 public preview，当前范围是库函数；从 Tile 调用开发者自定义的 __device__ 函数仍列为未来工作，相关库也需提供支持。因此不能据此推断任何 GPU、任何现有设备函数都能直接混用。[来源：官方公告的 CUDA Tile updates 章节](https://developer.nvidia.com/blog/nvidia-cuda-13-5-brings-nvidia-vera-rubin-ga-support/)。

调试方面，Nsight Perf SDK for AI 开放公开预览，为长时间训练和推理保留选定的 GPU、CPU 性能指标与执行上下文；Nsight Compute 2026.4 提供时间线与函数统计，帮助定位平均值掩盖的阶段性停顿。实践上，可先固定一个实际训练或推理任务，在原版本与 13.5 下比较正确性、尾延迟、峰值显存及分析工具开销；使用 Tile 互操作时单独记录硬件互联和库版本。GA 平台支持、预览功能和某个应用的实测收益应各自验收，不能互相替代。[来源：官方公告的 New developer tools 及 Get started 章节；比较步骤为实践建议](https://developer.nvidia.com/blog/nvidia-cuda-13-5-brings-nvidia-vera-rubin-ga-support/)。
