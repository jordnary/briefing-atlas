GitHub 于美国太平洋时间 11 月 13 日 10:23（北京时间 11 月 14 日 02:23）宣布，Google 的 Gemini 4 Hydrogen 已在 GitHub Copilot 正式可用，面向 Pro、Pro+、Max、Business 和 Enterprise 用户逐步推出。公告列出的入口包括 VS Code、Visual Studio、CLI、coding agent、Copilot app、github.com、移动端、JetBrains、Xcode、Eclipse 和 SDK；暂时看不到模型选择项，并不等于账号永久不具备资格。

本条新增事实是 Copilot 的正式接入。为解释模型定位，背景窗口扩展到约 48 小时：Google 原始公告发布于 UTC 11 月 12 日 18:00，即北京时间 13 日 02:00。Google 把 Hydrogen 定位为日常编程、工具调用与多步骤任务的执行模型，提供 low、medium、high（默认）及 xhigh 四档思考等级，以及 100 万 token 上下文。Google 公布的直接 API 基础价格为每百万输入 token 1.50 美元、输出 7.50 美元；这是模型提供方公告价格，不能直接当作任意 Copilot 任务的最终账单。

GitHub 表示该模型在按用量计费下采用提供方标价，具体计费仍须结合 Copilot 的定价规则和实际用量核对。Business 与 Enterprise 管理员可通过模型策略控制访问：默认启用新模型时会自动放行，除非管理员关闭全局默认或显式禁用该模型。这意味着模型上架同时也是企业配置变化，不能只检查开发者界面有没有新选项。

更快、指令遵循更好以及图中的成绩属于供应商发布的信息，尚不能证明某个团队的代码修改成功率同步提高。模型切换可能改变工具调用次数、失败后的重试方式和实际 token 消耗。开发团队可用同一组修复 issue、运行测试与受约束重构任务，固定仓库、提示词和验收条件，对照现用模型记录通过率、总耗时、账单与越界修改；先确认每个实际客户端暴露的设置，再决定是否扩大默认使用范围。不要由底层模型具备四档思考等级，推断所有 Copilot 入口都能手动配置四档。

Reuters 于北京时间 11 月 14 日 21:07 报道，意大利数据保护机构就 Facebook Android 应用访问个人相册、向用户建议可发布内容的做法，对 Meta 处以 8.05 亿欧元罚款，报道折合约 8.87 亿美元。按报道对监管方结论的转述，相关处理未充分告知用户并取得必要同意，涉及约 2,000 万意大利 Android 用户；监管方要求 Meta 在 60 天内默认关闭该功能，并另行征求同意。

Meta 表示将上诉，认为罚款金额不成比例，并称应用读取照片前需要用户授予设备权限，用户也可以修改设置。双方争议不能简化为手机是否出现过一个授权弹窗：允许应用访问相册，与用户是否知悉具体分析、推荐及数据处理目的，是需要分别核验的问题。这里的处罚及整改要求按 Reuters 对监管方的报道归因，本条没有把尚未直接读取的原始裁决当作已独立审阅文件。

还须划清两个边界。第一，这项始于 2025 年的调查没有裁定照片是否被拿来训练 AI；Meta 否认这种用途，不能把本次罚款写成“AI 训练违法已被证实”。第二，Reuters 指出 2026 年推出的另一项云端处理功能仍留待另案评估。配图展示的是 Meta 公开介绍的云处理及创作建议产品背景，历史素材用于说明功能类别，不能将它与此次被处罚的具体旧功能合并。

对产品团队，这提供了一个具体的设计检查点：把“访问哪些文件”“在设备还是云端处理”“用于哪种推荐”“能否撤回”分别写清楚，并核对默认状态和撤回后的处理行为。用户则可检查 Facebook 的相册建议和系统照片权限是否分别符合自己的选择。后续应观察上诉进展、默认设置是否按要求调整，以及另案是否出现新的结论；当前报道不能替代这些尚未发生的结果。

GitHub 于美国太平洋时间 11 月 13 日 10:27（北京时间 11 月 14 日 02:27）宣布，GitHub Copilot app 对 GitHub Enterprise Server（GHES）的支持从自愿加入的预览转为正式可用。用户可以加入 GHES 账号，处理实例上的远程仓库、issues 和 pull requests；要求 Copilot app 1.2.0 或更高版本。此次新增事实是企业自托管服务的连接支持从预览转为正式可用。

连接流程仍有前置条件：先以 GitHub.com 或 GHE.com 账号登录，再在 Settings → Accounts → Add account 中选择 GitHub Enterprise Server。官方文档补充，使用 Copilot 还需要登录具有许可证的云账号，或者按文档配置自己的模型提供方。最关键的限制是公告明确写明：GHES 不支持 cloud sessions。

这让采用企业自托管 GitHub 的团队可以把既有仓库与桌面代理工作流接起来，但“托管位置”“模型服务”和“任务执行位置”仍是三个不同维度。不能由支持 GHES 推导出应用所有能力都可在企业内部离线运行，也不能把产品页的一般云端演示当成 GHES 的能力清单。

团队可先用无敏感数据的测试仓库验证账号切换、仓库权限、issue 与 PR 上下文，以及版本兼容性；再逐项确认实际使用的模型服务和会话类型。验收时保留一个明确的失败用例：尝试依赖 cloud sessions 的工作流应被识别为不适用，而不是默认沿用 GitHub.com 的操作方案。公开公告没有提供 GHES 接入的性能收益数据，生产收益需要用本团队任务验证。

来源：[GitHub《GitHub Enterprise Server support in the GitHub Copilot app》](https://github.blog/changelog/2026-11-13-github-enterprise-server-support-in-the-github-copilot-app)（2026-11-13；正式可用公告日期同日）；[官方登录文档](https://docs.github.com/enterprise-server@latest/copilot/copilot-on-ghes/sign-in-on-copilot-app)（持续更新文档，独立发布日期未披露，用于补充操作说明）。
