Anthropic 11 月 25 日发布工程报告，回顾其 Messages API 从 Python 迁移至 Rust 的过程。公司报告称，每请求 CPU 用量下降约 70%，首 token 延迟中位数下降约 20%。此前，公司曾把输出解析交给 Rust，但每个输出 token 要三次跨越语言边界，CPU 用量仅下降约 8% 至 10%。[迁移报告](https://www.anthropic.com/research/migrating-api-to-rust)

这次迁移的难点在于判定新旧实现何时等价。模型输出本身可能变化，旧服务也在继续迭代。团队用生产中的旧实现作为参照，在流量中检查协议和处理行为的差异。准备做类似迁移的团队可以先给流式事件顺序、工具调用与失败响应定义比较规则，再分别监测每请求 CPU、首 token 延迟和协议差异率。[验证方法](https://www.anthropic.com/research/migrating-api-to-rust)

配图归档说明：官方博客的两段演示以 Vimeo 视频嵌入，没有找到可独立归档的公开静态演示画面。9to5Mac 的题图主要展示产品名称和标志，因此本条保留一张有性能数据的图表。

PrismML 的公告标注 11 月 24 日。本条使用 72 小时窗口，因为发布方公开了权重体积相同的两代模型的任务级比较，可用于判断本地编码工作流的实际取舍。[发布公告](https://prismml.com/news/bonsai-2-5-27b)

新模型以 Qwen3.8 27B 为基础，发布方称权重体积仍为 5.9 GB，并以 Apache 2.0 许可发布。其自测中 SWE-bench Verified 从 60.8 升到 75.6，AppWorld 从 51.2 升到 90.5，LiveCodeBench v6 则从 83.8 降到 83.0。试用时可固定工具链和任务集，同时记录回归测试通过率、工具调用次数和运行时峰值显存。权重文件体积只覆盖部署开销的一部分。[技术白皮书](https://github.com/PrismML-Eng/Bonsai-demo/blob/main/bonsai-2-5-27b-whitepaper.pdf)
