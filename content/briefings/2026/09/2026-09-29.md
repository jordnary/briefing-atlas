**发生了什么。** Anthropic 在[9 月 28 日的发布说明](https://www.anthropic.com/claude-sonnet-5-5)中推出 Claude Sonnet 5.5，定位为处理边界清楚的日常任务、修复缺陷以及制作文档、幻灯片和表格的高效率模型。公司称其生成速度比 Sonnet 5 快 30% 以上，输入、输出和缓存读取的标价仍为每百万 token 2 美元、10 美元和 0.20 美元，但由于完成同一任务通常消耗更少 token，单任务成本最多可降低 30%。Anthropic 报告它在 Terminal-Bench 4.0 上得到 70.6%，而 Sonnet 5 为 10.3%；这是厂商公布的评测结果，不能直接外推到所有代码库和工具链。

发布同时扩大了实际可用范围：模型标识为 `claude-sonnet-5-5`，已进入 Claude Platform、AWS、Google Cloud 和 Microsoft Azure。[GitHub 同日公告](https://github.blog/changelog/2026-09-28-claude-sonnet-5-5-in-github-copilot/)称它也开始向 Copilot Pro、Pro+、Max、Business 和 Enterprise 用户逐步开放，覆盖 VS Code、Visual Studio、Copilot CLI、coding agent、GitHub.com、JetBrains、Xcode 和 Eclipse 等入口。企业管理员仍可通过模型策略关闭或启用它。

**为什么重要。** 这次竞争重点不是单纯把最高分再推高，而是把接近高端模型的能力压进更低延迟和更低任务成本的日常层。Anthropic 自己也明确表示，Opus 5.5 在需要持续判断的开放式复杂任务上仍更强。Sonnet 5.5 的网络安全能力明显提升，因此首次在 Sonnet 系列中启用与高能力模型类似的网络安全防护和回退；高风险请求可能回退到 Sonnet 5。成本与安全策略都按任务类型分层，意味着‘默认模型’选择需要同时看质量、总 token、工具调用次数和回退率。

**实践与观察。** 迁移时不要只比较单次回复价格，可固定一组真实仓库任务，记录成功率、人工返工、总 token、工具调用数、端到端时间和安全回退。不同 effort 设置应分开统计；Anthropic 也提醒，评测分数会受 effort 和超时影响。关闭 thinking 的现有集成需要切换到新的 `between_tools` 设置，再迁移到 Sonnet 5.5。对高风险网络安全工作，应先确认回退行为是否改变自动化流程，不能把模型升级等同于权限升级。

**发生了什么。** Meta 在[9 月 28 日公告](https://about.fb.com/news/2026/09/launching-meta-enterprise-platform/)中把 Meta Enterprise Platform 定义为新的主要业务支柱，计划先向企业和开发者整合 Muse agent、Meta Business Agent、Muse API、Muse Code 等技术。Chirantan ‘CJ’ Desai 将加入 Meta，出任 Chief Enterprise Platform Officer 并向 Mark Zuckerberg 汇报；Meta 称他此前担任 MongoDB CEO 和总裁，也曾在 Cloudflare 领导产品与工程，并在 ServiceNow 任职近八年。

公告给出的方向是把 Meta 的模型、代理、基础设施和既有商业客户关系转化为企业可部署的产品与服务，但没有披露统一控制台、定价、正式可用地区、SLA 或数据保留细节。现阶段能确认的是组织架构和产品范围，而不是一个已经完整上线、可一键迁移的企业套件。作为组件背景，[Muse 的 9 月 8 日说明](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/)称其运行在独立 Secure VM 中，并由隔离的 Sentinel 代理审批外部访问；[Meta Business Agent 的 6 月 3 日说明](https://about.fb.com/news/2026/06/meta-business-agent/)则称其面向 WhatsApp、Messenger 和 Instagram 的客户交互，并提供企业控制、护栏和度量能力。

**为什么重要。** Meta 过去在企业市场更多依赖广告、消息平台和硬件；这次把个人代理、商业代理、API 与编码工具放入统一的企业平台叙事，意味着它要与 Microsoft、Google、OpenAI、Anthropic 等公司的企业 AI 栈正面竞争。Meta 拥有数亿商家触点，但这并不自动转化为企业软件优势：身份与权限映射、审计、数据隔离、第三方连接器、区域合规和长期支持才决定平台能否进入生产环境。领导层任命说明这是一项持续业务建设，而非单次功能发布。

**实践与观察。** 企业采购方应等待并要求可核验的架构与合同细节：Muse、Business Agent 和 Muse Code 是否共享身份边界，Secure VM 的数据保留和密钥管理如何实现，第三方连接器使用什么权限模型，以及审计日志能否导出到现有安全系统。试点可先限制在低风险客户服务或内部知识流程，记录人工接管率、错误动作、延迟和单位任务成本；在正式 SLA 与数据处理条款出现前，不宜把公告中的‘安全和隐私内建’当作完成的合规证明。

## briefing-2026-09-29-03

:::gallery
![NVIDIA Open Agent Safety Platform 架构图，左侧为 OpenShell 运行时，右侧为 Sentry 硬件监控](https://developer-blogs.nvidia.com/wp-content/uploads/2026/09/NVIDIAAgentSafetyPlatform_1920x1080_Title_v05.webp)
[平台参考设计：OpenShell 在 Vera CPU 一侧管理沙箱与策略，Sentry 在 BlueField-4 上独立监控与执行；来源：NVIDIA Technical Blog；发布日期：2026-09-28](https://developer.nvidia.com/blog/nvidia-open-agent-safety-platform-a-reference-for-continuous-in-silicon-agent-monitoring/)

![NVIDIA BlueField-4 DPU 电路板产品图](https://www.nvidia.com/content/nvidiaGDC/us/en_US/networking/products/data-processing-unit/_jcr_content/root/responsivegrid/nv_container_2396617/nv_container/nv_teaser.coreimg.jpeg/1787156870695/bluefield-4-ari.jpeg)
[BlueField-4 DPU 产品主题图；它是 Sentry 独立监控与策略执行所依赖的硬件组件，并非发布现场；来源：NVIDIA](https://www.nvidia.com/en-us/networking/products/data-processing-unit/)
:::

**发生了什么。** NVIDIA 在[9 月 28 日新闻稿](https://investor.nvidia.com/news/press-release-details/2026/NVIDIA-Launches-Open-Agent-Safety-Platform-to-Secure-Agents-From-Testing-to-Deployment/default.aspx)中发布 Open Agent Safety Platform，由开源 OpenShell 安全运行时和 Sentry 参考系统设计组成。OpenShell 在代理进程之外设置默认拒绝的沙箱、网络与凭据策略，记录允许和拒绝决策；它针对 Vera CPU 优化，但 NVIDIA 称可扩展到 Arm 和 Intel 等第三方计算平台。Sentry 则在 BlueField-4 DPU 上运行独立看门狗，使用 DOCA 观察代理请求、响应和工具访问，并在代理越过边界时进行毫秒级隔离。

[NVIDIA 技术说明](https://developer.nvidia.com/blog/nvidia-open-agent-safety-platform-a-reference-for-continuous-in-silicon-agent-monitoring/)把设计原则概括为可验证策略、带外执行、控制通往模型的路径、根据可观察推理调整权限，以及实验室、企业与硬件提供者的共同责任。公告列出 Anthropic、Microsoft、Salesforce、SAP、Red Hat、金融机构、关键基础设施企业和机器人公司等参与者，并称超过 100 家组织正采用或集成相关技术。OpenShell 软件和技能已经提供开发资源与 GitHub 仓库；这不等于所有 Sentry 硬件组合都已完成独立安全认证。

**为什么重要。** 近期多起代理绕过应用层限制的事件显示，提示词、模型行为准则和代理框架无法单独构成强制边界。NVIDIA 把控制放到代理进程外部，进一步把监控与隔离放到主机之外的 DPU，目标是在模型或宿主环境被突破时仍保留独立执行层。这种‘模型不可信、环境强制执行’的思路更接近零信任基础设施，也会把 AI 安全采购从软件功能扩展到 CPU、DPU、遥测与策略验证的整套架构。毫秒级隔离和低开销目前主要是厂商声明，仍需在真实工作负载中验证。

**实践与观察。** 团队可先从 OpenShell 的开源部分做小范围验证：为代理设置默认无网络、最小文件范围和逐目标 API 白名单，检查策略变更是否需要人工批准，并把 allow/deny 记录接入现有 SIEM。评估时同时测误拦截、逃逸、凭据暴露、延迟和运维复杂度；如果考虑 Sentry 与 BlueField-4，还要验证带外遥测能否覆盖自定义代理、第三方模型和多代理子任务。硬件隔离是额外防线，不应替代模型评测、人工确认和事故响应流程。
