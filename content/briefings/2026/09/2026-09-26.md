**发生了什么。** Microsoft 在 9 月 25 日[公布新版 Copilot](https://blogs.microsoft.com/blog/2026/09/25/introducing-the-new-copilot-with-home-code-and-autopilot/)：Home 汇集 Chat、Cowork 和 Office 文档工作；Code 可按自然语言需求建立应用、追踪器、仪表板或工作流，采用 GitHub Copilot 的底层技术，并在隔离环境中运行；Autopilot 是有自身身份、记忆与工作区的持续代理，可按目标跟进线程、周期任务与项目。公告将 Home 和 Code 列为接下来数周进入 Frontier，Autopilot 计划在月底扩大私人预览。为企业应用提供运行环境的 Copilot Managed Runtime 已进入预览。发布范围和时间是厂商计划，并非所有租户今天都能用到。

**为什么重要。** 这次调整把即时问答、可编辑 Office 成品、小型软件构建和长期代理任务纳入同一产品路径，组织既要管理数据权限，也要管理任务持续运行后的成本与审计。Microsoft 同时区分订阅制的日常 Copilot 使用与 Cowork、Code、Autopilot 等按量计费的代理工作；因此“能让代理做更多事”会直接影响预算和审批流程。持续代理的实际可靠性、权限边界与费用仍需在预览中检验。

**实践与观察。** 已使用 Microsoft 365 的团队可挑一个有明确输入与验收标准的小型内部流程，分别记录人工修改次数、端到端完成率、权限拒绝与每次成功任务的费用。试用 Code 时核实生成应用的托管和数据访问范围；试用 Autopilot 时先规定触发条件、可执行动作和人工接管点，并跟踪跨天任务是否正确恢复。

配图归档说明：公告正文只有一张可独立反映功能的 Teams 截图；其社交分享图沿用同一会话画面，属于近似重复。检索配套文档后尚未找到可核实、互补的 Slack 或任务回链截图，因此保留单图例外，不以 Logo 或重复裁切凑数。

**发生了什么。** GitHub 于 9 月 25 日[更新 Copilot 在 Slack 与 Microsoft Teams 的公开预览](https://github.blog/changelog/2026-09-25-updates-to-github-copilot-for-slack-and-microsoft-teams/)：Slack 可把受支持的文件、附件与消息链接作为上下文；Teams 可利用内嵌图片、转发消息及频道线程历史。代理在建立新 issue 前会检查相似 issue，并把新建工作与原始讨论相互链接。用户还可在对话中切换模型，Slack 可设默认负责人和仓库。GitHub 表示长任务中断恢复、过期回复与大型频道处理也得到改进。

**为什么重要。** 团队常在聊天中提出需求，却在 GitHub 上实施；来源消息、附件和产出 issue 若断开，代理容易重复建单或丢失关键约束。此次更新试图把聊天上下文带进开发工作，并让完成结果回指讨论来源。不过，GitHub 明确称能力正在逐步推出；公开预览仅面向 Copilot Business 和 Enterprise 组织，使用量计入现有权益与云代理预算。

**实践与观察。** 试点团队可选一条从 Teams 或 Slack 进入 issue 的真实流程，检查附件内容是否被正确引用、相似 issue 是否被识别、生成 issue 是否保留原线程链接；再观察断线后是否产生重复答复或错误仓库操作。管理员应先核对云代理策略、连接范围和预算，再根据实际可用的预览功能设计试验。
